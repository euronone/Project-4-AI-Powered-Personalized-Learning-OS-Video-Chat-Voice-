# Admin Guide

## Supabase Dashboard

### Monitoring Users

1. Go to **Authentication → Users** in the Supabase dashboard
2. View all registered students, their sign-up dates, and email confirmation status
3. Manually confirm or block users if needed

### Database Management

- **Table Editor**: Browse and edit rows in `students`, `subjects`, `chapters`, `activities`, `student_progress`, `sentiment_logs`
- **SQL Editor**: Run ad-hoc queries (use caution in production)
- **Logs**: View Postgres query logs under **Logs → Postgres**

### Storage

- **marksheets bucket**: Private bucket containing student-uploaded marksheets
  - Files are stored at path `<student_uuid>/<filename>`
  - Access is controlled by Row Level Security — students can only read their own files
- **content bucket**: Public bucket for AI-generated diagrams and media

### RLS Policies

All tables have Row Level Security enabled. The FastAPI backend uses the **service role key** which bypasses RLS. Frontend Supabase JS client uses the **anon key** subject to RLS.

Key policies to verify:
- `students`: Users can only SELECT/UPDATE their own row (`auth.uid() = id`)
- `subjects`, `chapters`, `activities`: Joinable back to student_id → `auth.uid() = student_id`
- `sentiment_logs`: `auth.uid() = student_id`

## Redis

### Monitoring Cache

Using Upstash or Redis CLI:

```bash
# View cached sentiment keys
redis-cli -u $REDIS_URL keys "sentiment:*"

# Inspect a value (format: "emotion:confidence")
redis-cli -u $REDIS_URL get "sentiment:<student_uuid>:<chapter_uuid>"
```

Sentiment cache entries have a TTL of 60 seconds and expire automatically.

### Flushing Cache

In emergencies (e.g., stale data bug):

```bash
redis-cli -u $REDIS_URL flushdb   # clears ALL keys — use with caution in production
```

## Database Migrations (Alembic)

### Apply pending migrations

```bash
cd backend
alembic upgrade head
```

### Roll back one migration

```bash
alembic downgrade -1
```

### View migration history

```bash
alembic history
alembic current
```

### Create a new migration

```bash
alembic revision --autogenerate -m "add_new_column"
# Review the generated file in backend/alembic/versions/ before applying
```

## Content Moderation

AI-generated curriculum content (chapters, activities) is generated by Claude with structured prompts that:
- Restrict output to K-12 appropriate content
- Enforce JSON-only responses with required fields
- Validate against a grade-level schema

If inappropriate content is reported:
1. Access the `chapters.content_json` field via Supabase Table Editor
2. Manually edit or nullify the `content_json` field to trigger regeneration on next student access
3. Update the system prompt in `backend/app/services/curriculum_generator.py` if the issue is systemic

## Quota and Rate Limiting

Current implementation relies on:
- **Anthropic API**: Managed by Anthropic's rate limits per API key tier
- **OpenAI Realtime API**: Per-project quotas in OpenAI dashboard
- **Redis**: Used for sentiment caching (not request rate limiting in current version)

To add request rate limiting, use `slowapi` (Python) middleware in `backend/app/main.py`.

- Auth logs: Supabase Dashboard → Logs → Auth
- API logs: Supabase Dashboard → Logs → Edge Functions (if using edge functions)
